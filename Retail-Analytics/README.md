# Retail Sales Analytics — Portfolio Project

A complete, end-to-end data analytics project built for a resume/portfolio:
**Python (cleaning + EDA) → PostgreSQL (SQL analysis) → Metabase (dashboard)**.

Every script in this repo has been tested and runs as-is. You're not just
copying a tutorial — you'll actually generate data, clean it, load it into a
real database, write real SQL, and build a real dashboard you can screenshot
for your resume/LinkedIn/portfolio site.

---

## 1. Why this project (and how to talk about it)

This project is designed to hit the three skills almost every entry-level
Data Analyst job posting asks for:

| Skill | What you'll demonstrate |
|---|---|
| **Python** | Data generation, cleaning messy real-world data (nulls, duplicates, inconsistent formatting), EDA with pandas/matplotlib |
| **SQL** | Schema design, joins, CTEs, window functions, aggregate queries, a customer segmentation (RFM) query |
| **Dashboarding** | A live, interactive Metabase dashboard connected to a real database |

The dataset simulates an e-commerce business: customers, products, and
orders. It's synthetic (generated by a script, not downloaded), which means
it's 100% reproducible — no dead Kaggle links, and you can regenerate it
anytime, tweak volumes, or add complexity.

**Resume bullets you'll be able to write honestly after finishing this**
(see `RESUME_BULLETS.md` for the full set).

## 3. Step-by-step walkthrough

### Step 0 — Prerequisites

Install Python, PostgreSQL, and Metabase first. Full OS-specific instructions
are in **[INSTALLATION.md](INSTALLATION.md)** — do that now, then come back here.

Quick check everything's ready:
```bash
python3 --version      # 3.9+
psql --version          # 14+
```

### Step 1 — Get the project files and set up a virtual environment

```bash
mkdir retail-analytics-project && cd retail-analytics-project
# copy in the data/, python/, sql/ folders from this guide

python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r python/requirements.txt
```

### Step 2 — Generate the raw dataset

```bash
cd data
python3 generate_data.py
cd ..
```

This creates `customers_raw.csv`, `products_raw.csv`, and `orders_raw.csv`
— about 800 customers, 60 products, and 8,000+ order line items across two
years. The data is *intentionally messy*: some missing emails, inconsistent
name casing, duplicate rows, missing quantities, inconsistent status casing
(`"completed"` vs `"Completed"`). That's on purpose — cleaning messy data is
the actual skill employers care about.

### Step 3 — Clean the data with pandas

```bash
python3 python/01_data_cleaning.py
```

Open `python/01_data_cleaning.py` and read the comments — each cleaning
decision (imputing missing quantity with the per-product median instead of
dropping rows, standardizing casing, filling missing emails with an explicit
placeholder instead of leaving NaN) is something you should be ready to
explain in an interview. **This is the step to talk about most** — anyone
can call `.dropna()`; explaining *why* you chose a specific imputation
strategy is what separates a junior analyst from someone who just ran a
script.

### Step 4 — Exploratory Data Analysis

```bash
python3 python/02_eda.py
```

This prints summary stats (total revenue, return rate, cancellation rate)
and saves four charts to `python/eda_charts/`:

- Monthly revenue trend
- Revenue by category
- Order status breakdown
- Revenue by region

Drop 1–2 of these into your project's GitHub README or portfolio page as
preview images.

### Step 5 — Set up PostgreSQL and load the data

Create the database and schema:
```bash
createdb retail_analytics
psql -d retail_analytics -f sql/01_create_tables.sql
```

Open `python/03_load_to_postgres.py` and edit the `DB_USER` / `DB_PASSWORD`
constants to match your local Postgres setup, then:
```bash
python3 python/03_load_to_postgres.py
```

Verify it worked:
```bash
psql -d retail_analytics -c "SELECT COUNT(*) FROM orders;"
```

### Step 6 — Run the SQL analysis

Open `sql/02_analysis_queries.sql`. It contains 8 queries, ordered by
increasing complexity:

1. Monthly revenue trend
2. Top 10 products by revenue
3. Revenue & margin by category
4. Customer lifetime value (top 20)
5. Month-over-month revenue growth (`LAG()` window function)
6. **RFM customer segmentation** (Recency/Frequency/Monetary, using `NTILE()`)
   — this is the one to lead with in interviews, it shows you can do more
   than basic aggregation
7. Return rate by category
8. New vs. returning customer revenue per month

Run them individually to explore:
```bash
psql -d retail_analytics -f sql/02_analysis_queries.sql
```
Or paste them one at a time into `psql`, DBeaver, or directly into
Metabase's native SQL editor (Step 7).

### Step 7 — Build the Metabase dashboard

1. **Start Metabase** (see INSTALLATION.md for the one-command Docker setup).
   Once running, open **http://localhost:3000** in your browser.
2. **First-time setup wizard**: create an admin account, skip adding sample
   data.
3. **Add your database**: *Admin Settings → Databases → Add a database*
   - Database type: **PostgreSQL**
   - Host: `localhost` (or `host.docker.internal` if Metabase is in Docker
     and Postgres is on your host machine — see note in INSTALLATION.md)
   - Port: `5432`
   - Database name: `retail_analytics`
   - Username / Password: whatever you set in Step 5
   - Click **Save**, Metabase will sync the schema automatically.
4. **Build questions (charts)** — for each one, click *New → SQL Query*,
   paste the matching query from `sql/02_analysis_queries.sql`, run it, then
   click **Visualize** and pick a chart type:

   | Query | Suggested chart type |
   |---|---|
   | Q1 Monthly revenue trend | Line chart |
   | Q2 Top 10 products | Bar chart (horizontal) |
   | Q3 Revenue & margin by category | Bar chart |
   | Q4 Customer lifetime value | Table |
   | Q5 MoM growth | Combo chart (bar + line) |
   | Q6 RFM segmentation | Table, or a pie chart of segment counts (add `GROUP BY segment` version) |
   | Q7 Return rate by category | Bar chart |
   | Q8 New vs returning revenue | Stacked bar chart |

   Save each one (e.g. "Monthly Revenue Trend", "RFM Segments").
5. **Assemble the dashboard**: *New → Dashboard* → name it "Retail Sales
   Performance" → add each saved question as a card → arrange into a
   sensible layout (KPI numbers top row, trend line next, category/segment
   breakdowns below).
6. **Add a filter**: click *Add a filter*, choose "Date" type, and connect
   it to the `order_date` field across your time-based cards — this makes
   the dashboard interactive and is an easy, visible way to show you
   understand dashboard UX, not just querying.
7. **Screenshot it.** This is your portfolio image.

### Step 8 — Push to GitHub

```bash
git init
git add .
git commit -m "Retail sales analytics: Python, PostgreSQL, Metabase"
git remote add origin https://github.com/<your-username>/retail-analytics-project.git
git push -u origin main
```

Add a `.gitignore` with at least:
```

__pycache__/
*.pyc

```
(Keep `data/*_raw.csv` committed so the repo is self-contained and anyone
can clone-and-run — or keep `generate_data.py` as the source of truth and
`.gitignore` the CSVs too, your call.)

Put 2–3 dashboard screenshots and the monthly revenue chart PNG directly in
the README so recruiters see results without cloning the repo.

## 4. Extending this project (optional, for a stronger resume line)

If you have extra time, any one of these turns "tutorial project" into
"project I made my own":

- Swap the synthetic data for a real public dataset (e.g., Kaggle's Online
  Retail II or a Superstore dataset) — same pipeline, real data.
- Add a `customer_churn.sql` query and a simple logistic regression in
  Python predicting which customers are at risk (ties in a light ML skill).
- Schedule `generate_data.py` differently to simulate daily incremental
  loads, and write a Python script that does an incremental (not full
  reload) load into Postgres — demonstrates ETL thinking.
- Containerize the whole thing with `docker-compose` (Postgres + Metabase +
  a script container) so anyone can run `docker-compose up` and have the
  full stack running — strong signal for more technical roles.
